# LoadXR

A minimal browser-based loading companion for Meta Quest, with an iPhone camera preview. Separate from the [original Load Guide](https://timohynninen.github.io/loadguide/).

## Use

On iPhone, open the HTTPS page in Safari, tap **Start camera preview** and allow the camera. Instructions appear in the upper right over live rear-camera video. **Previous** and **Next** move through the item loading sequence. The overlay stays fixed on screen, without spatial tracking. Stop camera, leaving the page or backgrounding it stops capture. Video stays in the browser without recording or upload.

In Meta Quest Browser, open the same HTTPS page and select **Enter mixed reality**. A head-relative panel sits above and to the right of the centre of view. Point a controller ray at Previous/Next and press the trigger. Exit using the headset system menu. Actual Quest passthrough, physical input, comfort and legibility still need hardware testing; Quest 2 is the first target, with Quest 3 intended through the same standards path.

The app uses the original guide's example shipment: 25 indivisible assemblies, 44 physical EUR pallets, nine front-to-rear stages and six declared stack pairings. The current item is highlighted in a miniature of the plan. Item numbers, colours, dimensions, weights, positions, handling notes and stack details come from the same validated sources. Navigation does not confirm loading or save progress.

## Develop

Run `node server.mjs`, then open http://localhost:4175/. Run `node --test tests/xr-sequence.test.mjs`. There is no package install or build step. Local HTTP on a remote phone does not enable camera/WebXR; use the HTTPS deployment for physical-device tests.

Runtime files are under `dist/`: vendored Three.js 0.180.0, plain JavaScript, CSS and the example JSON. No CDN, server backend, account or analytics. A separate `loadxr-v1` service-worker cache supports offline assets after the first visit. Camera/XR permission and device/browser support are still required.

`XR_PLAN.md` documents the design and platform sources. Browser QA used Codex's built-in browser, including 390 × 844 phone layout, all 25 steps, boundary buttons, and synthetic camera success/stop/denial. Actual iPhone camera selection/playback and Quest passthrough remain device acceptance checks. The synthetic camera fixture is generated by `node tests/prepare-xr-camera-check.mjs`; never publish the temporary `__xr-camera-check.html` file.

The GitHub Pages publishing checkout is `../../github-publish/loadxr`. It contains only the contents of `dist/`, this public README, library notices and `.nojekyll`. Pages uses main, repository root. Never publish the internal handoff, test fixtures or generated QA screenshots.
